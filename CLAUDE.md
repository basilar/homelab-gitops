# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this directory is

This is the **Flux GitOps root** for a single Talos Kubernetes cluster ("homelab"). It is *not* a self-contained project — it lives inside a larger repo (`~/Development/talos-linux/homelab/`) that also has `terraform/` (cluster + Flux bootstrap) and `talos/` (machine config). Flux on the cluster reconciles from `https://github.com/basilar/homelab-gitops` branch `main`, path `.` — meaning the in-cluster Flux is pointed at this exact directory in a remote mirror, so a push to `main` is a deploy.

There is no build, no test suite, and no CI. Validation happens by Flux reconciling and reporting `Ready=True` on the cluster.

## Layout

The root `kustomization.yaml` aggregates everything in a flat list with no `dependsOn` ordering:

- `flux-system/` — `gotk-components.yaml` (Flux v2.8.3, all 6 controllers including image-reflector + image-automation) and `gotk-sync.yaml` (the self-referential `GitRepository` + `Kustomization`). The `kustomization.yaml` here patches the root Flux Kustomization to add SOPS decryption via the `sops-age` secret.
- `infrastructure/` — `cert-manager`, `traefik`, `longhorn`, `authentik`. Each is a Kustomize dir with `namespace.yaml`, `helmrepository.yaml`, `helmrelease.yaml`, plus app-specific extras.
- `apps/` — `jellyfin`, `home-assistant`, `yayog-web-app`. The first two are placeholder dirs with empty `resources: []` lists.

`infrastructure/authentik/` and `apps/{jellyfin,home-assistant}/` are empty placeholders (`resources: []`); referenced from the root kustomization but currently deploy nothing.

## Key conventions

- **Helm-via-Flux pattern**: each infra component has `HelmRepository` + `HelmRelease` (chart from upstream registry, not vendored). Versions pinned with wildcards (e.g. `"1.7.*"`, `"39.*"`).
- **TLS**: cluster has a self-signed CA `ClusterIssuer` named `basilar-ca`. Cert resources reference it; hostnames use the `*.basilar.local` domain. The CA's public cert is committed at `infrastructure/cert-manager/basilar-ca.crt`.
- **Ingress**: Traefik v3 (chart 39.x) is the ingress controller. Service is exposed via Cilium LB-IPAM at `192.168.1.192` (annotation `io.cilium/lb-ipam-ips`). HTTP→HTTPS redirect is configured at the entryPoint level. New apps should expose themselves with `IngressRoute` (traefik CRD), not `Ingress`, and reference a cert-manager `Certificate` issued by `basilar-ca`. Example: `infrastructure/longhorn/{certificate,ingressroute}.yaml`.
- **Privileged namespaces**: `longhorn-system` and `traefik` have explicit `pod-security.kubernetes.io/enforce: privileged` labels. Add this to any namespace whose workloads need it; cluster default is more restrictive.
- **External-source apps**: `apps/yayog-web-app/` is the pattern for an app whose manifests live in a *different* repo. It declares its own `GitRepository` + `Kustomization` pointing at `./deploy/flux` in the external repo, with HTTPS auth via a SOPS-encrypted PAT secret.

## Secrets (SOPS + age)

`.sops.yaml` encrypts files matching `*.sops.ya?ml` with age recipient `age19vcs2wk277rpmnl32k346xxsanun7y5ulw0zrus03twnmk565ckq8r4hap`, fields `data` and `stringData` only (so `metadata`, `kind`, etc. stay readable).

The in-cluster age **private** key lives in the `sops-age` Secret in `flux-system` (bootstrapped out-of-band — not in this tree). Decryption is wired up by the SOPS patch in `flux-system/kustomization.yaml`.

To create a new encrypted secret:
```sh
sops --encrypt --in-place path/to/secret.sops.yaml
```
The recipient comes from `.sops.yaml` automatically; no key flags needed.

Never commit a `.sops.yaml`-suffixed file with plaintext `data`/`stringData`. Verify with `sops --decrypt` before committing.

## Common operations

All of these run against the cluster, not against this directory. `KUBECONFIG` is at `../../talos/config/kubeconfig` (gitignored, generated by terraform).

```sh
# See what Flux thinks of every Kustomization / HelmRelease / GitRepository
flux get all -A

# Force a reconcile after pushing changes (instead of waiting for the 5–10m interval)
flux reconcile source git flux-system
flux reconcile kustomization flux-system --with-source

# Tail logs for a specific controller
flux logs --kind=Kustomization --name=flux-system -f

# Dry-run a kustomize build locally (no cluster needed)
kustomize build .
kustomize build infrastructure/longhorn
```

## When making changes

- **Adding a new app/infra component**: create the dir, add `kustomization.yaml` listing its resources, then add the dir to the root `kustomization.yaml`. Without the second step, Flux ignores it.
- **Don't edit `flux-system/gotk-*.yaml` by hand** — they are generated by `flux install`/`flux bootstrap` and the comment at the top says so. Regenerate via terraform's `flux-bootstrap` module if controller set or version changes.
- **Image automation** (`image-reflector-controller`, `image-automation-controller`) is installed but `ImageRepository`/`ImagePolicy`/`ImageUpdateAutomation` CRs belong in `flux-system` namespace, not in app namespaces — see commit `22b3c70`.
- The cluster has **single-replica defaults** for stateful workloads (Longhorn `defaultReplicaCount: 1`, Traefik `replicas: 1`) — this is a homelab, not HA. Don't "fix" these without asking.
- After each set of changes you did, propose a good one liner commit message, do not commit just write the text in the console.
